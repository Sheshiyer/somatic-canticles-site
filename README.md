# Somatic Canticles — landing page

A launch page for the *Somatic Canticles* trilogy, built in the shape of
[`latent-spaces/brag`](https://github.com/latent-spaces/brag)'s own launch
site: the hero film is generated by running `/brag` on this page itself.

Zero-build static HTML/CSS/JS. No framework, no bundler.

## Local preview

```bash
bun scripts/serve.ts site 4321
```

Then open <http://localhost:4321/>.

## Checks

```bash
bun scripts/check-site.mjs   # structural + copy-safety checks against site/
bun scripts/contrast.ts      # WCAG contrast for every documented token pair
```

Both must exit `0` before a deploy.

## Buttondown

The reader-list forms post to Buttondown's embed-subscribe endpoint. The
username is set once, on `<html data-buttondown="...">` in
[`site/index.html`](site/index.html) — `main.js` rewrites both forms' `action`
from that single attribute. Until a real username is set, the literal
`BUTTONDOWN_USERNAME` placeholder is left in the markup so the page still
degrades sanely (the form simply won't subscribe anyone).

## Regenerating the hero film

`site/assets/brag.mp4` and `brag.jpg` are the real launch film: 15 s, made with brag's process on the house showreel engine, with no Remotion. The pipeline lives in [`film/`](film/README.md):

```bash
cd film && bun install
bun tools/audio.ts && bun run render && bun tools/mux.ts
bun tools/verify.ts && bun tools/verify.ts --web
```

`mux.ts` writes the poster (baked in as frame 0), the 1080p60 master in `brag-output/` (gitignored), the ≤ 8 MB web cut in `site/assets/`, and the share copy. It also re-stamps the film URLs.

## Hosting and asset loading

The site deploys to Cloudflare as the Worker `somatic-canticles-site` on `somatic.tryambakam.space`. Deploy with `bunx wrangler deploy`.

- **Static files:** everything under `site/` is served as static assets. Headers are set in `site/_headers`; `/assets/*` is cached `immutable` for a year.
- **Video:** only `/assets/*.mp4` runs through [`worker/index.ts`](worker/index.ts), which answers `Range` requests with `206 Partial Content`. Cloudflare static assets answer ranges with a full 200, and Safari/iOS will not play or seek a `<video>` without 206.
- **Cache-busting:** because assets are immutable, the film URLs carry `?v=<first 12 hex of the file's sha256>`. `film/tools/mux.ts` stamps them automatically via `bun scripts/stamp-assets.ts`, and `check-site.mjs` fails if a stamp does not match its file. Never edit the `?v=` values by hand.
